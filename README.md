sqlite3 school.db

sqlite> .read schema.sql

sqlite> .read data.sql

# 4. 쿼리 실행 (한꺼번에 실행)
sqlite> .headers on
sqlite> .mode column
sqlite> .read queries.sql
```
```
#1 — 테이블 수
총 4개의 테이블을 사용했다.

students — 학생 정보
teachers — 교사 정보
subjects — 과목 정보
grades — 학생 성적 정보
#2 — FK 무결성 테스트
존재하지 않는 student_id를 입력하여 FK 오류가 발생하는 것을 확인했다. 이를 통해 잘못된 데이터 입력이 차단되는 것을 확인했다.

#3 — 샘플 데이터 설명
학생, 교사, 과목, 성적 데이터를 실제 학교에서 사용할 수 있는 형태로 구성했다. 성적은 0~100점 범위로 입력했다.

#4 — 쿼리 목적
각 쿼리마다 무엇을 확인하기 위한 쿼리인지 한 줄 주석으로 설명했다.

#5 — 실행 결과
모든 쿼리의 실행 결과를 result.txt에 저장했으며, 중요한 쿼리는 실행 화면을 캡처하여 결과를 확인할 수 있도록 했다.

#6 — 테이블을 분리한 이유
학생, 교사, 과목, 성적은 서로 다른 역할을 가지므로 테이블을 분리했다. 이를 통해 데이터 중복을 줄이고 수정하기 쉽게 만들었다.

#7 — FK와 1:N 관계
grades.student_id는 해당 성적이 어떤 학생의 것인지 연결한다. 한 학생이 여러 성적을 가질 수 있으므로 students : grades = 1 : N 관계이다.

#8 — 자료형을 선택한 이유
이름과 과목명은 문자열이므로 VARCHAR를 사용했고, 학생 번호와 점수는 숫자이므로 INTEGER를 사용했다.

#9 — 인덱스를 사용한 이유
학생 이름으로 검색하는 경우를 고려하여 students.name에 인덱스를 생성했다. 자주 검색되는 컬럼의 조회 성능을 높이기 위해 사용했다.

#10 — DB와 엑셀의 차이
엑셀보다 DB는 테이블 간 관계를 PK와 FK로 표현할 수 있고, 제약조건을 통해 잘못된 데이터 입력을 막을 수 있다는 장점이 있다.

#11 — PK와 FK의 차이
PK는 각 데이터를 고유하게 구분하는 값이고, FK는 다른 테이블의 PK를 참조하여 테이블을 연결하는 값이다.

#12 — INNER JOIN과 LEFT JOIN
INNER JOIN은 양쪽 테이블에 모두 존재하는 데이터만 조회한다. LEFT JOIN은 왼쪽 테이블의 모든 데이터를 조회하고 연결되는 데이터가 없으면 NULL로 표시한다.

#13 — GROUP BY와 집계 함수
GROUP BY는 같은 값을 가진 데이터를 그룹으로 묶는다. COUNT는 개수, SUM은 합계, AVG는 평균을 계산할 때 사용한다.

#14 — 복잡한 JOIN 쿼리
먼저 grades에서 성적을 가져오고, students와 JOIN하여 학생 이름을 가져온다. 이후 subjects와 JOIN하여 과목 이름을 가져와 최종 성적 정보를 완성한다.

#15 — 작업 중 발생한 문제와 해결
FK 때문에 부모 테이블에 없는 데이터를 입력할 수 없는 문제가 있었다. 부모 테이블의 데이터를 먼저 INSERT한 후 자식 테이블의 데이터를 입력하는 순서로 수정하여 해결했다.
