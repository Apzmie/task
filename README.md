```
# --- 1. 환경 설정 및 데이터 저장 ---
# 최대 메모리를 30바이트로 제한 (키/값 길이를 합쳐 30 이상이면 LRU 정책 발동)
CONFIG SET maxmemory 30
# "user:1" (6글자) + "Alice" (5글자) = 11바이트 사용
SET user:1 "Alice"
# "user:2" (6글자) + "Bob" (3글자) = 9바이트 사용 (누적: 20)
SET user:2 "Bob"
# "user:3" (6글자) + "Charlie" (7글자) = 13바이트 사용 (누적: 33) 
# -> 30바이트 초과 발생! 가장 오래된 'user:1'이 LRU에 의해 자동으로 삭제됨
SET user:3 "Charlie"

# --- 2. LRU 및 메모리 상태 확인 ---
# 'user:1'은 이미 삭제되었으므로 (nil) 반환. 'user:2'가 가장 최근 사용된 것으로 갱신됨
GET user:1
# 현재 메모리 사용량과 삭제된 키(evicted_keys) 개수 확인
INFO memory
# 현재 남아있는 키 목록 확인 ('user:1'이 삭제되었는지 검증 가능)
KEYS

# --- 3. TTL (만료 시간) 테스트 ---
# 새 데이터 저장
SET user:4 "David"
# 'user:4'에 5초의 유효기간 설정 (5초 뒤 자동 삭제 예약)
EXPIRE user:4 5
# 5초 이내에 호출하면 남은 시간(초)을 반환
TTL user:4

# --- 4. 만료 후 조회 ---
# 5초 대기 후 조회하면 이미 만료되었으므로 삭제됨 (nil 반환)
GET user:4
# 이미 삭제되었으므로 존재하지 않는 키를 의미하는 -2 반환
TTL user:4
```
```
1. KEYS / DBSIZE 출력
DBSIZE는 저장된 키의 개수를 (integer) 형식으로 출력하고, KEYS는 저장된 모든 키를 Redis와 비슷한 형태로 출력하도록 구현했습니다.

2. maxmemory = 0
maxmemory가 0이면 메모리 제한이 없는 것으로 처리했습니다. 따라서 메모리가 가득 차더라도 LRU 삭제는 발생하지 않습니다.

3. INFO memory
INFO memory는 used_memory, maxmemory, evicted_keys를 각각 key:value 형태로 출력하여 보기 쉽고 파싱하기 쉽게 구성했습니다.

4. TTL 검증
같은 키에 EXPIRE를 여러 번 설정할 수 있기 때문에, 힙에서 꺼낸 만료 시간이 현재 저장된 만료 시간과 같은지 확인한 후 삭제하도록 설계했습니다. 오래된 만료 정보는 무시합니다.

5. 에러 메시지
모든 에러는 Redis와 비슷한 형식으로 통일했습니다. 잘못된 명령어, 인자 개수 오류, 정수 변환 오류, 메모리 부족 오류를 각각 구분하여 출력합니다.

6. 연결 리스트 안전성
노드를 삭제할 때 None이나 잘못된 노드가 들어오지 않도록 확인하여 연결 리스트가 깨지는 상황을 방지했습니다.

7. 해시 함수
문자 하나씩 계산하는 다항식 해시(Polynomial Hash)를 사용했습니다. 31을 곱해 계산하여 문자열이 비교적 고르게 분산되도록 했으며, 평균적으로 빠른 검색이 가능합니다.

8. 체이닝 방식
같은 해시값이 나오면 하나의 버킷에 여러 데이터를 저장하는 체이닝 방식을 사용했습니다. 현재는 새 노드를 생성하지만, 이후에는 삭제된 노드를 다시 사용하는 방식으로 확장할 수 있습니다.

9. 리해시
데이터가 많아져 로드 팩터가 0.75를 넘으면 버킷 크기를 2배로 늘리고 모든 데이터를 다시 저장합니다. 이렇게 하면 검색 성능을 계속 유지할 수 있습니다.

10. HashMap과 LRU
HashMap은 데이터를 빠르게 찾는 역할을 하고, 이중 연결 리스트는 최근 사용 순서를 관리하는 역할을 합니다. 두 자료구조를 함께 사용하여 조회와 LRU 갱신을 모두 빠르게 수행합니다.

11. GET의 시간 복잡도
GET은 HashMap에서 데이터를 찾고 연결 리스트에서 위치만 변경하므로 평균적으로 O(1) 의 속도를 가집니다. 다만 해시 충돌이 많아지면 최악의 경우 O(n) 이 될 수 있습니다.

12. Heap과 ttl_map
Heap은 가장 빨리 만료되는 키를 찾는 역할을 하고, ttl_map은 각 키의 최신 만료 시간을 저장합니다. 두 구조를 함께 사용하여 오래된 TTL 정보가 잘못 처리되지 않도록 했습니다.

13. Eviction과 Expire
메모리 부족으로 삭제된 키는 evicted_keys에 기록합니다. TTL이 지나 자동으로 삭제된 키는 Eviction과 구분하여 관리할 수 있도록 설계했습니다.

14. GET에서 만료 확인
GET을 실행하면 먼저 키가 만료되었는지 확인합니다. 만료되었다면 삭제 후 (nil)을 반환하고, 만료되지 않았을 때만 LRU 순서를 갱신합니다.

15. LFU 확장
현재는 가장 오래 사용하지 않은 데이터(LRU) 를 삭제합니다. LFU를 적용하려면 가장 적게 사용한 데이터를 삭제하도록 각 데이터의 사용 횟수를 함께 저장하면 됩니다.

16. 대용량 데이터
데이터가 많아질수록 검색 속도가 느려질 수 있습니다. 이를 해결하기 위해 데이터를 여러 서버에 나누어 저장하는 샤딩(Sharding) 을 사용할 수 있습니다. 또한, 하나의 작업이 끝날 때까지 기다리는 대신 여러 작업을 동시에 처리하는 방법을 사용할 수 있습니다.

17. used_memory 계산
이번 프로젝트에서는 키와 값의 문자열 크기만 메모리 사용량으로 계산했습니다. HashMap, 연결 리스트, 힙 등의 자료구조가 사용하는 메모리는 계산하지 않았기 때문에 실제 Redis의 메모리 사용량과는 차이가 있을 수 있습니다.
```
